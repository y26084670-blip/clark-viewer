# 3D-кадры E3D Viewer: правила для AI и сопровождающих

Обновлено: 2026-09-21 16:58 UTC+3.

Актуально для версии 4.6.6. Основной сценарий — вкладка «Источники и поля 3D»
(`SourcesFields3D.jsx`) и быстрое переключение времени при чтении результатов.

## Контракт показа

- Во время чтения нового шага сохраняется последний полностью подготовленный
  кадр того же задания, величины, набора выбранных объектов и бюджета выборки.
  Строка состояния отдельно сообщает о чтении и указывает **показанный шаг**.
  Ползунок указывает запрошенный шаг; временное различие намеренное.
- Геометрия с движением и результат получают время из одного опубликованного
  кадра. Нельзя переводить геометрию на запрошенный шаг, пока результаты ещё старые.
- При смене задания, величины, выделения или бюджета старый результат сбрасывается.
  Порядок идентификаторов в одинаковом выделении не меняет контекст.
- Ошибка актуального чтения показывается явно. Предыдущий кадр того же контекста
  остаётся видимым со своим номером шага; его нельзя выдавать за новый результат.
- Устаревшие ответы и ошибки не публикуются. Закрытие вкладки отменяет ожидающий
  запуск и запрещает публикацию поздних ответов.

## Закрытие меню верхней панели

`ResultsGeometryViewport` закрывает открытое подменю при pointerdown снаружи
панели и её нажатой кнопки. Обработчик документа использует capture-фазу,
не отменяет щелчок и удаляется при закрытии панели/компонента. Поэтому щелчок
по сцене одновременно закрывает меню и сохраняет штатное управление камерой.
Внутренние элементы не закрывают меню; повторное нажатие исходной кнопки
закрывает его один раз, другая кнопка переключает панель. Вложенные настройки
источников следуют тому же правилу. Активное оформление и aria-expanded
всегда производны от openPanel. Escape и клавиатурные виды сохраняются.

## Начальное выделение

При успешной загрузке задания `App.load` выделяет все исходные ID элементов и
областей, а не только первую строку. Массивы выбора принадлежат App и общие
для 3D, «Рабочих точек» и вкладок поля. Переход между вкладками не меняет
ручного выбора, включая пустой. Повторная успешная загрузка задания снова
выделяет всё; неудачная или устаревшая загрузка не меняет активный выбор.
Это правило списка, а не принудительная команда показа: конкретная величина
по-прежнему отображает только объекты с соответствующими результатами.

## Чтение, потоки и очередь

`ResultService` владеет HDF5 Web Worker текущего задания. Worker монтирует файлы
через WORKERFS при открытии задания. Для шага читаются нужные срезы dataset,
а не открывается заново весь файл. Буфер типизированного массива передаётся
основному потоку через transferable `ArrayBuffer`.

`resultFrameController.js` работает в основном потоке. Он разрешает одно
выполняющееся чтение **кадра** и хранит один заменяемый ожидающий запрос.
Кадр может состоять из нескольких HDF5-срезов выбранных объектов/образов.
События до очередного `requestAnimationFrame` объединяются; во время чтения
запоминается только последний запрос. Уже выполняющееся чтение не прерывается,
worker не уничтожается при движении ползунка. Промежуточные шаги могут быть пропущены.

`readObjectFrames` ждёт завершения всех срезов кадра, в том числе при ошибке одного
из них (`Promise.allSettled`). Иначе следующий кадр мог бы начать чтение, пока
срезы предыдущего ещё стоят в очереди worker.

`useResultFrame` подключает контроллер к 3D и «Поле на линиях»; для линии
контекст дополнен компонентой, направлением и режимом образов.
[Контракт графика](AI_CHART_RENDERING.md). Остальные вкладки сохраняют
поведение `useAsyncResult`. История временных кадров не кэшируется.
Построение DTO геометрии, преобразование результатов в векторы/скаляры,
подготовка буферов и Three.js выполняются в основном потоке браузера.

## Ресурсы Three.js

`ThreeGeometryViewport` объединяет изменения в один RAF: размер canvas при
необходимости, геометрия, заданные источники, векторы, скаляры, затем отрисовка.
Canvas меняет физический размер только при изменении размеров контейнера;
изменение размера и следующий render выполняются в одном callback.

При совместимой топологии сохраняются объекты, материалы, текстуры и ёмкость
буферов. Обновляются атрибуты `position`/`color`, instance matrices, `drawRange`,
число экземпляров, bounding volumes и сведения для выбора мышью. Рост ёмкости
освобождает заменённую геометрию/instance buffer; смена стиля освобождает старый
стиль. Нулевая величина скрывает отрезок вектора, сохраняя его узел.

Для движения `geometryRevision` связывает проекции времени с исходной моделью.
Повторное использование разрешено только при совпадении модели, фильтров,
режима, бюджетов и физических образов. Координаты пересчитываются относительно
фиксированного опорного кадра, а не предыдущего Float32-кадра: ошибка не накапливается.
Вместе обновляются рёбра, вершины, дискретизация и координаты выбора мышью.
Изменение исходной модели/топологии допускает полную замену геометрии.

Сохранённые XYZ и векторы HDF5 уже находятся в основной СК: движение,
амплитуду и симметрию к ним повторно **не применять**. Скрытые сохранённые
слои исключаются из raycasting через `traverseVisible`. При закрытии viewport
все удерживаемые ресурсы освобождаются штатным cleanup.

Не возвращать очистку результата на каждое движение времени, безусловный
`renderer.setSize`, уничтожение/создание слоёв на каждый шаг или неограниченную
очередь HDF5. Увеличение мощности GPU этих причин мигания не устраняет.

## Проверка

Для изменения 4.6.6 (база `8a2223242571eab889f93cd7c3218744aa423e0e`) фактически
прошли production-сборка, пять проверок `node --test test/geometryKeyboard.test.js`
и 22 браузерные проверки настоящего ResultsGeometryViewport в headless Chromium
153/Playwright: пять верхних меню, закрытие снаружи, повторная кнопка, внутренние
элементы, переключение панелей, вложенные настройки, Escape и повторное открытие
компонента. Ошибок JavaScript нет. Использовалась пустая геометрия; чтение
реальных HDF5 и численные результаты этим прогоном не проверялись.

`npm test`: контроллер проверяется с управляемыми задержками/ошибками,
переключением контекста и закрытием; ресурсные тесты используют реальные функции
Three.js, проверяют идентичность объектов, рост ёмкости, нулевые значения,
актуальность picking metadata и отсутствие накопления ошибки движения.
Существующие HDF5-тесты проверяют REAL32/REAL64, выборки и физические величины.
`npm run build:release` проверяет production-сборку.

Для браузерной регрессии: загрузить MH.h5 с несколькими шагами и движущимся
элементом, замедлить чтение и быстро запросить последовательность шагов.
Проверить сохранение старого слоя, публикацию последнего шага, совпадение
времени геометрии и результатов, неизменность камеры и числа GPU-ресурсов.
Повторить для векторов и скаляров, с вершинами/дискретизацией, ошибкой чтения,
пустым выделением, сменой задания и закрытием. Проверить подсказку в сохранённом
узле после движения. Автотест в программном WebGL подтверждает эти инварианты,
но не заменяет оценку плавности на пользовательском GPU и большом файле.
