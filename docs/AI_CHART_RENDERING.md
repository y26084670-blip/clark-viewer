# Графики E3D Viewer: правила для AI и сопровождающих

Обновлено: 2026-09-20, UTC+3. Актуально для 4.6.4.

## Владелец и область действия

`src/components/LineChart.jsx` владеет экземпляром Chart.js, кривыми,
масштабом, рамкой увеличения, перемещением и легендой. Компонент используется
несколькими вкладками. Флаг `freezeAutoScale` включён только в
`src/tabs/FieldLines.jsx` («Поле на линиях»); остальные графики сохраняют
автоматический диапазон до ручного изменения масштаба.

## Масштаб поля на линиях

При входе на вкладку создаётся новый компонент. До первого непустого набора
конечных точек автошкалирование ожидает данные; пустой начальный canvas
не фиксирует диапазон 0…1. После первого показа фактические пределы Chart.js
по обеим осям сохраняются как явные `min/max`.

После этого смена шага времени не выполняет автошкалирование. Кнопка «Авто»
однократно подбирает пределы по **показанным** данным и снова фиксирует их.
Если показанных точек ещё нет, команда ожидает первые пригодные данные.
Рамка левой кнопкой и перемещение правой продолжают менять масштаб вручную;
Esc отменяет незавершённое действие.

Изменение величины, компоненты, направления, образа или выделения не является
неявной командой «Авто»: пределы остаются прежними, подписи осей обновляются.
Для нового диапазона пользователь нажимает «Авто». После ухода и повторного
входа вкладка заново подбирает пределы по первому показанному кадру.

## Чтение и согласованность кадра

`FieldLines` использует `useResultFrame`, общий с 3D контроллер
`resultFrameController.js`, и загрузчик `readLineFrame` из `resultRequests.js`.
Одновременно допускаются один читаемый кадр и один заменяемый ожидающий запрос.
Изменения до ближайшего RAF объединяются. Уже начатые срезы завершаются,
промежуточные запросы времени могут быть пропущены.

В контекст входят задание, величина, набор исходных ID выбранных объектов,
бюджет выборки, компонента, направление, номер локального образа и режим всех
образов. Только смена времени сохраняет прежние кривые. Изменение контекста
сбрасывает несовместимые данные. Порядок тех же выбранных ID не меняет контекст.

Во время чтения и при ошибке следующего шага сохраняется последний готовый
кадр того же контекста. Строка состояния сообщает о чтении/ошибке и указывает
**показанный шаг**. Ползунок показывает запрошенный шаг; эти номера временно
могут различаться. Устаревшие ответы/ошибки не публикуются, закрытый компонент
не принимает поздний ответ. Новая величина не подписывает старые кривые.

`readLineFrame` читает либо выбранный LS-срез каждой подходящей области, либо
все образы через `readObjectFrames`. Недоступный номер LS перечисляется в
диагностике. Все срезы кадра завершаются через `Promise.allSettled`, даже если
один уже завершился ошибкой: очередь не запускает новый кадр поверх хвоста
предыдущего. Сам HDF5 читается Web Worker текущего задания; формирование
`lineSeries`, управление очередью и Chart.js работают в основном потоке.
[Общий механизм чтения](AI_3D_RENDERING.md#чтение-потоки-и-очередь).

## Ресурсы и другие графики

Chart.js создаётся один раз при монтировании и уничтожается при cleanup.
Новые данные заменяются в существующем экземпляре через `update("none")`,
без анимации. При совпадении подписи и позиции кривой сохраняется её объект
набора данных и состояние видимости. Меняется массив точек, подписи осей и
настройки отображения; обработчики подсказки и наложенной легенды читают
актуальные серии, не замыкают первый кадр.

`FieldLines` мемоизирует опубликованный кадр и серии: сообщение о начале
чтения само по себе не запускает обновление графика. Размер canvas управляется
responsive-механизмом Chart.js, без удаления/создания canvas на каждом шаге.
В остальных вкладках не включать фиксацию первоначального автомасштаба без
отдельного требования. Для них сохраняется сброс ручных пределов при смене
подписей осей. Переключение легенды и копирование таблицы/картинки сохраняются.

## Проверка

`npm test`: `test/resultFrameController.test.js` проверяет объединение запросов,
сохранение предыдущего кадра, контексты линии, ошибки, закрытие, выбор LS,
перечень пропущенных областей и завершение соседних срезов при ошибке.
Остальные тесты проверяют REAL32/REAL64 HDF5, порядок узлов, серии, zoom/pan,
истории результатов и повторное использование ресурсов 3D.

Браузерный сценарий: реальный HS.h5 с двумя областями и 101 шагом; замедлить
чтение, быстро запросить 1…100, проверить отсутствие пустого промежуточного
графика, подпись показанного шага, идентичность Chart/набора данных и неизменные
оси. Нажать «Авто», затем выполнить рамку/перемещение, сменить время и проверить
сохранение пределов. Проверить ошибку чтения, пустое выделение и восстановление,
уход/возврат на вкладку. Для общего выбора — загрузка задания, ручное снятие
выделения, переход между вкладками и повторная загрузка.

Фактически выполнено 2026-09-20: 82/82 теста и production-сборка успешно.
Браузерный сценарий выполнен в headless Chromium с реальным HS.h5 через
штатный HDF5 Worker и тестовыми файловыми дескрипторами. При серии запросов
1…100 прочитаны только шаги 1 и 100 (по два среза областей); Chart и наборы
данных сохранены, пределы 1…4 / 1…8 не изменились. «Авто» расширил ось Y до
100…900 по показанному шагу 100. Проверены zoom/pan, ошибка чтения, пустой
выбор, возврат на вкладку с новым автомасштабом, начальное выделение всех
объектов, ручное выделение между вкладками и повторная загрузка.
Также проверены обычный автомасштаб общего LineChart и переключение видимости
наложенной легендой с сохранением выбора при обновлении данных. Ошибок страницы
нет. Системный диалог выбора каталога и субъективная плавность на пользовательском
GPU в этот прогон не входили.
