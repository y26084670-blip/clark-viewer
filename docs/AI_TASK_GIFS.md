# GIF и DOCS выбранного задания

Обновлено: 2026-10-21 02:10 UTC+3.

<a id="task-docs"></a>
## GIF/DOCS — 4.46.0

Правая панель содержит локальные вкладки GIF (N) и DOCS (N). N — число
изображений; обе вкладки доступны при нулевом счётчике. DOCS находится рядом
с input3XX; непосредственные PNG/JPEG/WebP показаны сверху, TXT/MD в UTF-8 —
снизу. Начальный выбор: README.txt, README.md, первый текст по имени. Markdown
отображается буквально. Изображения и текст используют общий модальный просмотр.

Подробные правила хранения, форматов, лимитов и жизненного цикла — в
[каноническом контракте Editor](https://github.com/y26084670-blip/clark-editor/blob/main/docs/AI_UI_CONTRACTS.md#task-docs-gallery).
[Практический сценарий](https://y26084670-blip.github.io/clark-editor/user-guide/index.html#task-docs).
Viewer передаёт `candidate()?.handle` и `refreshKey={candidate()}`, поэтому
повторный выбор строки обновляет и изображения, и текст. Скрытая локальная
галерея перечисляет имена для счётчика, но освобождает URL и не читает байты.
Просмотр DOCS не создаёт каталоги, не записывает файлы и не запрашивает разрешение
на запись. GIF сохраняет прежнее подтверждение удаления и проигрыватель.

## Первый этап 4.18.0 — однокадровые файлы

Имя 3D-файла включает обозначения выбранных величин перед 3d: J_3d_...,
M_B_3d_... и т.д. Однокадровый статический GIF проходит те же операции сохранения,
предпросмотра и удаления, что динамический. Расширение .gif, каталог output3XX/demo,
проверка имени, разрешения и правило выбора свободного суффикса не меняются.
Отдельный формат хранения и изменения Editor не требуются.

## Область и владельцы

С версии 4.13.0 первая вкладка Viewer показывает галерею GIF из
`output3XX/demo` выбранного задания. Аналогичная галерея есть в Editor 4.41.0.
Это необязательные иллюстрации результатов; они не меняют входные данные
решателя, HDF5, загрузку модели или состояние несохранённых правок Editor.

Общие файлы копируются между проектами без изменений:

- `src/components/tasks/TaskMediaPanel.jsx` и `.css`: локальные вкладки и счётчики.
- `TaskImageGallery.jsx`, `TaskMediaDialog.jsx`, `TaskGifGallery.css` в том же каталоге: общая сетка и окно.
- `TaskGifGallery.jsx`, `TaskDocsGallery.jsx`: GIF-плеер/удаление и документация только для чтения.
- `src/services/taskImageGalleryController.js`, `taskDocsService.js`, `taskDocsTextController.js`: очередь изображений, файловое чтение DOCS и очередь выбранного текста.
- `test/taskDocs.test.js`, `test/browser/taskMedia.html`, `test/browser/taskMedia.fixture.jsx`, `scripts/check-task-media-browser.mjs`: сервисные и браузерные проверки DOCS/общей панели.
- `src/components/tasks/TaskGifPlayer.jsx`: canvas и управление воспроизведением.
- `src/services/taskGifPlayback.js`, `taskGifDecoder.js`, `src/workers/taskGifDecode.worker.js`: таймеры, композиция и декодирование.
- `test/taskGifPlayback.test.js`, `test/taskGifDecoder.test.js`: состояние плеера и синтетические GIF.
- `src/services/taskGifGalleryController.js`: асинхронное состояние и Blob URL.
- `src/services/taskGifService.js`: операции File System Access API.
- `test/taskGifGallery.test.js` и `test/taskGifService.test.js`: проверки этих границ.

`src/tabs/Tasks.jsx` передаёт handle выбранной строки и активность вкладки.
В Viewer это `candidate`, а не уже загруженное задание. Во время удаления
выбор задания и конфликтующие файловые операции блокируются через
`onBusyChange`. В скрытой вкладке галерея не читает файлы.

Средняя панель сохраняет строки `minmax(240px, 3fr) minmax(160px, 2fr)`.
Правая выделяет строку переключателям GIF/DOCS и делит оставшуюся высоту 3:2
без фиксированного минимума, чтобы текст оставался доступен при 600 px высоты.
Подпись 20 px, промежуток 10 px, внутренний отступ 20 px, граница 3 px.
Текст результатов остаётся под галереей в локальной вкладке GIF.

## Галерея и время жизни

Сетка прокручивается вертикально, количество колонок зависит от доступной
ширины. У каждой ячейки есть имя, открытие и удаление справа вверху.
Предпросмотр открывается в отдельном тёмном `<dialog>`, перемещается за
заголовок, закрывается кнопкой или Escape. Его GIF имеет собственный Blob URL,
поэтому прокрутка ячейки за пределы сетки не прерывает просмотр.
С Viewer 4.17.0 / Editor 4.42.0 общие CSS задают ручное изменение размера
за нижний правый угол и вписывание canvas с сохранением пропорций. Кнопка □
разворачивает окно в viewport с отступом 8 px, повторная восстанавливает
прямоугольник с ограничением текущими границами. В развёрнутом виде drag отключён.

При каждом открытии начинается один проход; «Циклически» выключен независимо
от loop-extension файла. «Стоп» удерживает кадр; «Старт» продолжает оставшуюся
задержку, а после завершения запускает фильм сначала. Для статического GIF
кнопка недоступна. Ошибки чтения/декодирования показываются в окне.

`gifuct-js` 2.1.2 (MIT) разбирает GIF в module Worker. Кадры декодируются по
одному, выполняется композиция прозрачности и disposal 2/3. Хранятся сжатые
данные и постоянное число RGBA-буферов, а не вся декомпрессированная анимация.
Лимиты: файл 128 МиБ, canvas 16 777 216 пикселей, не более 10 000 кадров;
некорректные границы/палитры отклоняются. Нулевая задержка заменяется на 100 мс,
положительные задержки сохраняются, включая 10 мс. При паузе во время
декодирования готовый кадр удерживается до продолжения. Закрытие/смена задания
уничтожает Worker и таймер, поздние ответы игнорируются. Изменение размера
окна не перезапускает фильм. Миниатюры остаются обычными img.

Удаление требует отдельного диалога подтверждения с именем файла и задания.
Нажатие окончательной кнопки «Удалить» непосредственно вызывает файловый
сервис: разрешение записи не зависит от времени чтения подтверждения.
При смене задания подтверждение и предпросмотр закрываются.

Список перечитывается при выборе задания, возвращении на вкладку, обновлении
данных задания, фокусе окна, кнопке обновления и уведомлении сервиса об успешной
записи/удалении. Нет фонового опроса таймерами. Отсутствие папки или файлов —
нормальное пустое состояние; ошибки доступа показаны отдельно.

Миниатюры читаются только при попадании ячейки в видимую часть сетки
(`IntersectionObserver`, запасной вариант — проверка прямоугольников при
прокрутке/изменении размера). Одновременно выполняется не более двух чтений;
открытый предпросмотр получает приоритет в очереди. Отменённый, но ещё не
завершившийся Promise занимает слот до завершения. Перечисление каталога также
последовательное. Epoch контекста и AbortSignal не позволяют поздним ответам
прежнего задания менять текущую галерею. URL освобождаются при выходе ячейки
из видимости, закрытии предпросмотра, смене контекста и удалении компонента.

<a id="crossfade"></a>
## Плавное воспроизведение — Viewer 4.33.0 / Editor 4.51.0

`TaskGifGallery` передаёт `crossfade={maximized()}`: смешивание включается
только после разворачивания окна кнопкой □. Обычное окно галереи, её миниатюры
и предпросмотр после создания фильма сохраняют обычный показ.
Файл GIF, его задержки, декодер и формат Worker не меняются.

В этом режиме `taskGifPlayback` заранее запрашивает один следующий полный
кадр. Текущий и следующий кадры смешиваются через `requestAnimationFrame`
на двух вспомогательных canvas. `putImageData` заполняет эти поверхности
только при смене кадра; `drawImage` складывает взвешенные премультиплицированные
пиксели, включая прозрачность, с `globalCompositeOperation="lighter"`.
Размер выходного canvas присваивается только при изменении размеров GIF.
Хранится постоянное число кадров/поверхностей, а не вся распакованная анимация.

Коэффициент перехода вычисляется по прошедшему времени в интервале исходного
кадра. Например, задержка 500 мс остаётся интервалом 500 мс для перехода.
Пропущенная промежуточная отрисовка не растягивает интервал; поздний ответ
декодера продолжает прежнюю временную шкалу. Фактическое ожидание при медленном
декодировании или перегрузке браузера возможно, отдельной задержки crossfade нет.
Нулевая задержка по-прежнему заменяется декодером на 100 мс.

«Стоп» удерживает текущую смесь, «Старт» сохраняет её прогресс и оставшееся
время. При восстановлении размера показывается полный текущий исходный кадр,
но его оставшееся время, Worker и положение в фильме сохраняются. В одиночном
проходе последний кадр остаётся полным; в цикле он смешивается с первым.
Отключение цикла на последнем кадре прекращает этот переход и удерживает
полный последний кадр. Однокадровый GIF не запускает смешивание.
Закрытие, смена задания/файла и ошибка отменяют таймер, requestAnimationFrame
и Worker; поздние ответы прежнего Worker игнорируются.

Смешивание изображений не интерполирует результаты расчёта: контуры движения
могут временно двоиться. Отметки последнего открытого проекта/задания и их JSON
описаны в [AI_TASK_SELECTION.md](AI_TASK_SELECTION.md).

## Файловый контракт

`listTaskGifs(taskHandle, { signal })` возвращает `{ name, handle }[]` только
для файлов с расширением `.gif` без учёта регистра. Чтение использует
`create: false`: отсутствующие `output3XX/demo` не создаются и разрешение
записи не запрашивается. `readTaskGif(handle, { signal })` проверяет размер
до 128 МиБ и сигнатуру GIF87a/GIF89a; ошибку декодирования затем показывает UI.

`saveTaskGif(taskHandle, blob, suggestedName, { signal })` и
`deleteTaskGif(taskHandle, entry, { signal })` вызывают
`taskHandle.requestPermission({ mode: "readwrite" })` до первого `await`, из
явного нажатия пользователя. При отказе операция завершается понятной ошибкой.
Мутации последовательно проходят общую очередь; сигнал проверяется после
ожиданий перед следующим изменением. Удаление ограничено выбранным именем
GIF непосредственно в `output3XX/demo`, без рекурсивных операций.

Папки создаются только при явном сохранении. Сервис сохраняет предложенное
базовое имя, очищает запрещённые символы и зарезервированные имена Windows.
Если имя занято, добавляет `_2`, `_3` и далее; сравнение не зависит от регистра.
Перед открытием потока имя и содержимое проверяются повторно. Запись считается
успешной после `close()`, при ошибке поток прерывается. File System Access API
не предоставляет атомарного exclusive-create: нельзя гарантировать защиту от
сторонней программы, одновременно создающей или заменяющей тот же путь.
`isSameEntry` проверяет соответствие handle пути, а не уникальную идентичность
файла до внешней замены. Собственные операции приложения сериализованы.

При ошибке незавершённая пустая запись удаляется только после повторной
проверки пути, нулевого размера и исходного `lastModified`. Замеченное внешнее
изменение оставляется с диагностикой. Если первый снимок созданного файла
прочитать не удалось, сервис сообщает имя возможного пустого остатка.
Поздняя отмена после успешного `close()` уже сохранённый файл не удаляет.

`subscribeTaskGifs(listener)` уведомляет галереи после завершённой мутации и
возвращает функцию отписки. Ошибка слушателя не меняет результат файловой
операции. Эти функции не обращаются к DOM и не управляют выбранным заданием.

## Сохранение фильма

Диалог Viewer записывает GIF в задание, для которого фильм был создан:
используется сохранённый handle загруженной модели, а не текущий `candidate`
первой вкладки. Без флажка «в задании» остаётся скачивание браузером.
С версии 4.14.0 флажок отмечен при каждом открытии диалога записи.
Готовый Blob не теряется при отказе записи; можно повторить попытку либо
снять флажок. Формат имени с коротким обозначением вкладки и локальной
датой/временем описан в [AI_MOVIE_EXPORT.md](AI_MOVIE_EXPORT.md).
