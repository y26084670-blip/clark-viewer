# Редактируемый протокол задания

Обновлено: 2026-10-30 20:16 UTC+3.

Канонический контракт протокола Viewer. В версии 4.64.0 добавлена вставка
из буфера обмена. Протокол открывается командой «Инструменты → Протокол»
и хранится в `<task>/DOCS/*.html`.
Это самостоятельный документ для просмотра без Viewer и сети.
Интерактивная геометрия требует JavaScript/WebGL 2; текст, снимки и видео
остаются доступны без JavaScript.
Создание и повторное редактирование выполняются в Viewer; сохранённый HTML
открывается из DOCS в браузере. Формат и файловый сервис поддерживают повторное
чтение документа без первоначальных файлов результатов HDF5.

## Интерактивная геометрия и порядок блоков

Новый протокол содержит, в указанном порядке:

1. **3D-геометрия системы** — исходные элементы и области со всеми заданными
   локальными, азимутальными, периодическими и зеркальными образами.
2. Текст `input3XX/_summary.txt` отдельным блоком.
3. Текст `output3XX/_summary_out.txt` отдельным блоком, до строки
   «Файлы результатов:». Эта строка и весь остаток файла исключаются.
4. Материалы, отмеченные флажком «В протокол».
5. Все текстовые документы TXT/MD непосредственно из DOCS: каждый отдельным
   блоком с именем файла и исходным содержимым, в естественном порядке имён.
6. Все `output3XX/demo/*.webm` в конце.

`conditions.json` исключён; команды его добавления нет. Отсутствующая сводка,
папка DOCS или папка WebM пропускается.
`protocolSummaries.js` читает только UTF-8-текст сводок. Предел одной сводки —
2 МиБ; большой хвост с описанием файлов результатов не считывается целиком.
Имена файлов, чтение и порядок не зависят от пользовательского выбора видов.

`protocolDocs.js` использует штатные `listTaskDocs` и `readTaskDocsText`:
только прямые TXT/MD в UTF-8, до 2 МиБ каждый; вложенные каталоги, HTML
и изображения не включаются. Ошибка доступа, кодировки или размера
останавливает создание с именем файла; документ не пропускается молча.
Пустые текстовые документы также получают блок с именем. Исходные файлы
не меняются, текст экранируется как текст и доступен в автономном HTML.

В первом блоке кнопка **«Открыть 3D»** включает автономный просмотрщик:
левая кнопка мыши — вращение, колесо — масштаб, правая — перемещение.
Флажки управляют видимостью элементов/областей вместе с их образами;
«Показать все» и «Скрыть все» меняют весь список. Доступны ракурсы ±X/±Y/±Z
и «Исходный вид», возвращающий камеру, центр и масштаб. На узких экранах
список объектов располагается под сценой и прокручивается.

Сохраняется геометрия исходного задания, цвета материалов и названия объектов;
данные поля и временные шаги в интерактивный блок не включаются.
`protocolSceneData.js` преобразует штатный `buildGeometryScene` в отдельные
массивы координат/индексов и матриц образов, не меняя исходную модель.
Геометрия не дедуплицируется: вложенность симметрий соответствует решателю.
Неполное преобразование, нечисловые координаты или превышение 20 000 образов /
1 000 000 развёрнутых вершин останавливают создание с ошибкой.

PNG исходного вида находится внутри блока. При печати используется этот PNG,
в том числе если интерактивная сцена была открыта и повёрнута. При выключенном
JavaScript остаётся снимок; при недоступном WebGL 2 появляется пояснение.
Редактор протокола показывает тот же просмотрщик в iframe с
`sandbox="allow-scripts"`, без same-origin и доступа к файлам Viewer.
В DOCS миниатюра остаётся статической; кнопка ⤢ открывает полный HTML.

`protocolScenePlayer.js` используется для снимка и интерактивного отображения.
`build-protocol-scene.mjs` собирает Three.js/OrbitControls в один IIFE без
внешних импортов и вычисляет SHA-256 его точных байтов. Код, лицензия MIT,
геометрия и снимок включаются в HTML; ни CDN, ни исходные файлы не требуются.
CSP разрешает только этот хеш, изображения/видео data: и встроенные стили;
внешние загрузки и произвольный код запрещены. Generated-модуль исключён из git
и автоматически формируется перед `npm test`, `npm run dev` и каждой сборкой.

## Скачивание из списка заданий

В 4.67.0 значок листа со стрелкой вниз в строке задания открывает сохранённый
HTML в отдельной вкладке. Для одного файла — сразу; для нескольких — после
выбора из списка с именами, датами и размерами. Подсказка начинается с «Открыть
протокол». Escape/«Закрыть» закрывают список и возвращают фокус кнопке.
Область поиска: непосредственные `*.html` в `<task>/DOCS`, без учёта регистра,
без подкаталогов, TXT/MD и comparison. Метаданные сканируются по шесть заданий.

Справа вверху открытой страницы постоянно доступна «Загрузить». Она сохраняет
исходный HTML с прежним именем побайтно, включая встроенные 3D, изображения,
JSON и WebM. При открытии скачивание не начинается. Нативные настройки браузера
определяют папку загрузок или показ окна выбора места сохранения.

`protocolOpenWindow.js` резервирует вкладку непосредственно при нажатии,
сбрасывает `opener` и отображает исходный Blob в отдельном iframe без пересборки.
URL принадлежит вкладке протокола; уже открытый документ и его загрузка
работают после смены задания/проекта и закрытия Viewer. Закрытие вкладки
освобождает URL. Незавершённое чтение отменяется при смене списка или cleanup;
пустое окно закрывается при отмене, ошибке чтения или удалённом исходнике.
Блокировка всплывающего окна объясняется рядом с кнопкой. Лимит — 256 МиБ.

`TaskProtocolDownload.jsx` и `protocolOpenWindow.js` синхронны с Editor;
адаптеры `protocolDownloads.js` используют собственные зависимости приложений.
Загрузка задания, запись в каталог, запуск solver и открытие редактора протокола
не требуются. Выделение строки и загруженная модель сохраняются. Сохранение
HTML в Viewer обновляет индикаторы через `docsRevision`; внешние изменения
проверяются обновлением списка. Неизменившиеся метаданные чтение не прерывают.

## Выбор видов

Флажок «В протокол» сохраняет снимок текущего вида и момента времени, а не
подписку на дальнейшие изменения графика. Для замены снимка надо снять и
поставить отметку снова. Флажок устанавливается после успешного захвата;
ошибка показывается рядом с ним. Переключение вкладок сохраняет снимки.
Успешная загрузка задания сбрасывает все отметки и снимки; ошибка загрузки
сохраняет прежнее задание и его выбор. Дозапись диапазонов не является новой
пользовательской загрузкой задания.

- Источники / Поле 3D: флажок перед кнопкой справки, снимок с текущим ракурсом.
- Рабочие точки и Поле на линиях: последний элемент панели графика.
- Поле в областях: справа общей панели, X/Y/Z объединены в одно изображение.
- Графики: отдельный снимок каждого графика; в обычном размере только флажок
  с подсказкой, в развёрнутом также подпись. Статическая таблица сохраняется
  таблицей HTML. Удаление графика снимает его отметку.

`ProtocolCheck.jsx` использует существующий lifecycle захвата renderReady /
prepare / capture / restore через `protocolCapture.js`. Восстанавливаются
масштаб, видимость кривых, ракурс и время. Захват блокирует другие операции,
имеет отмену и предел ожидания 15 секунд. App владеет коллекцией снимков.
Все доступные поля «Комментарий» при создании протокола и добавлении снимков
пусты. Шаг/время остаются в подписи снимка. У сводок (`source: "summary"`)
поля комментария нет; другие блоки допускают ввод. Пустая строка или одни
пробелы не создают видимого абзаца в HTML. При повторном чтении сохранённого
протокола введённые пользователем комментарии сохраняются.

## Файл и повторное редактирование

### Вставка из буфера обмена — 4.64.0

Кнопки «Вставить рисунок» и «Вставить текст» в компоновщике читают буфер
только при явном нажатии. `protocolClipboard.js` преобразует изображение
в PNG, а текст читает как обычный текст с сохранением строк и абзацев.
Разметка HTML в тексте не исполняется. Растровые представления PNG, JPEG,
WebP, GIF и BMP принимаются, если браузер предоставляет их через Clipboard API;
для GIF вставляется статический рисунок. Предел — 8192×8192 пикселей и
16 МиБ для PNG data URL, текст — 2 МиБ UTF-8. Чтение требует доступного
Clipboard API и разрешения браузера; отказ или неподходящее содержимое
показываются в диалоге без изменения протокола.

Каждая вставка получает отдельный ID и обычный блок `image` или `text`
с пустым комментарием. Схема HTML не меняется. Штатный `appendProtocolBlocks`
вставляет блок после сводок и уже добавленных материалов, перед документами
DOCS и анимациями. Существующие блоки сохраняют относительный порядок.
Для вставок доступны комментарий и удаление; повторная вставка создаёт
новый блок. Вставки и комментарии входят в черновик текущего задания и файла,
сохраняются при закрытии/перечитывании и записываются в HTML только по
«Сохранить в DOCS». PNG и текст включаются в автономный HTML целиком.

Чтение буфера блокирует изменение состава и сохранение до завершения,
но окно можно закрыть. Закрытие, смена задания/протокола и размонтирование
отменяют применение результата; поздний ответ не попадает в другой документ.
ImageBitmap освобождается также при ошибке или отмене.

Проверки: `test/protocolClipboard.test.js` проверяет текст, границы размера,
форматы, отказ доступа, отдельные ID и отмену. `scripts/check-protocol-browser.mjs`
проверяет реальные text/PNG-вставки Chromium, новые и существующие протоколы,
черновики, повторное чтение, ошибки, отмену и автономный HTML.

### Автоматические WebM

При создании нового документа после геометрии, сводок, отмеченных снимков и TXT/MD из DOCS
автоматически добавляются все файлы `output3XX/demo/*.webm` текущего задания.
Регистр расширения не важен; порядок соответствует галерее анимаций.
Подкаталоги, соседние задания, GIF и файлы вне штатной папки не включаются.
Флажки «В протокол» выбирают снимки и не ограничивают список WebM.
Добавление новых снимков помещает их перед текстами DOCS, сохраняя WebM в конце.

`protocolMedia.js` использует существующие `listTaskGifs`/`readTaskGif`:
не меняет общие с Editor правила хранения и не создаёт/удаляет исходные файлы.
Сначала проверяется весь список и суммарный размер, затем файлы последовательно
кодируются в base64 кусками. Отсутствие папки означает пустой список.
Ошибка чтения/неверный контейнер/превышение размера останавливают создание
с указанием файла; ролики не пропускаются молча. Закрытие диалога отменяет чтение.

Видео встроены в `<video controls preload="metadata" playsinline>` как
`data:video/webm;base64,...`; воспроизведение, пауза и перемотка обеспечиваются
браузером без JavaScript, сети, Viewer, исходных WebM или путей к заданию.
При повторном чтении существующего HTML используются только включённые в него
данные: добавленные позже или удалённые исходные ролики не меняют документ.
Комментарии и удаление блоков доступны так же, как у снимков.

### Формат

`protocolDocument.js` владеет схемой `clark-viewer-protocol`, версия 3.
Версии 1/2 продолжают читаться и сохраняться; добавление видео повышает версию
как минимум до 2, добавление геометрии — до 3. Документы без геометрии сохраняют
статический формат. В одном HTML находятся блоки, PNG/WebM, стили и JSON в
`script[type="application/json"]#clark-protocol-data`. Только при наличии сцены
добавляется встроенный просмотрщик с точным CSP-хешем. Идентификатор документа, дата создания и стабильные
идентификаторы блоков переживают последующее открытие. Известные блоки:
`scene`, `image`, `video`, `text`, `table`. Данные проверяются перед чтением и записью;
неизвестная версия или тип блока отклоняются, а не пропускаются.

WebM хранится в HTML ровно один раз — в `src` элемента video. Служебный JSON
сохраняет `mediaRef` (индекс блока), имя файла, комментарий и идентификатор.
Парсер восстанавливает `dataUrl` из соответствующего video; отсутствующие или
дублирующиеся ссылки отклоняются. Такой формат не удваивает объём видео и
не требует исполняемого кода. CSP разрешает `media-src data:`, внешние ресурсы
запрещены. Для версии 3 с геометрией дополнительно разрешён только встроенный
скрипт с контрольным хешем.

Новый протокол включает путь от имени выбранного базового каталога и тексты
сводок по указанным выше правилам. Абсолютный путь ОС браузер не предоставляет.
Условия из старого сохранённого HTML остаются его текстом и могут быть удалены
как обычный блок; новой загрузки или обновления `conditions.json` нет.
Необязательное поле текстового блока `source` принимает `summary` или `docs`;
версии формата 1/2/3 и обычные текстовые блоки без этого поля совместимы.

### Открытие HTML из DOCS

Во вкладке «Выбор задания» выберите строку задания, DOCS и нужный HTML.
Кнопка ⤢ открывает исходный документ отдельной вкладкой браузера, включая
протоколы Viewer. Загружать задание или результаты HDF5 не требуется.
`taskDocsBrowser.js` создаёт Blob URL без фильтрации исходного HTML: скрипты,
графики, переключатели и скачивание работают. `opener` сброшен, URL живёт до
закрытия вкладки; Reload и переключение задания в Viewer его не аннулируют.
Относительные ресурсы соседних файлов DOCS не преобразуются в URL.
Встроенный предпросмотр остаётся статическим и изолированным.

Три кнопки «Создать», «Править», «Удалить» предназначены только для README.txt.
При другом выбранном файле они выключены. Отсутствующий README создаётся через
пункт `README.txt (создать)`; после удаления выбран этот же пункт. Для HTML
эти действия не доступны. Панель не открывает редактор протокола кнопкой ⤢.
[Общий контракт Editor/Viewer](https://github.com/y26084670-blip/clark-editor/blob/main/docs/AI_UI_CONTRACTS.md#task-docs-gallery).

«Инструменты → Создать протокол» заново формирует документ из геометрии,
сводок, текущих отметок, текстов DOCS и WebM с именем `protocol.html`. При повторном создании сохранённый
`DOCS/protocol.html` заменяется после нажатия «Сохранить в DOCS»; автоматические
`protocol-2.html`, `protocol-3.html` больше не создаются. Окно сообщает о предстоящей
перезаписи. Открытие или закрытие окна без сохранения оставляет прежний файл.
Старые комментарии и блоки не подмешиваются в заново сформированный документ.
Для отдельного документа можно явно задать другое имя. Существующие файлы
не выбираются в меню создания; сохранённый HTML открывается из DOCS.

Комментарии и
состав блоков доступны для изменения без пересчёта графиков. «Добавить
отмеченные» добавляет только отсутствующие идентификаторы снимков; прежние
комментарии сохраняются. Удаление блока снимает соответствующую текущую
отметку, если она существует. При сохранении физически записывается весь
HTML, но содержательно изменяются только выбранные пользователем блоки.
Предпросмотр доступен в DOCS, через кнопку «Просмотр HTML» в редакторе
или обычное открытие файла. «Перечитать» заново читает текущий файл и отменяет
несохранённые изменения. После сохранения DOCS показывает обновлённый документ.

`taskProtocolService.js` владеет доступом к файлам. До «Сохранить в DOCS» нет
запроса write-разрешения или создания каталога. Имя ограничено конечным
именем `.html`; чужой HTML не заменяется. Перед записью существующий текст
сравнивается с открытой версией: изменение извне требует повторного открытия
или нового имени. Ошибка записи вызывает abort потока. Общий предел файла —
256 МиБ, максимум 200 блоков; исходный TXT/MD — до 2 МиБ. Один исходный WebM
ограничен существующим пределом галереи 128 МиБ. Предварительная оценка
учитывает расширение base64, окончательная — точный размер HTML. Это не формат
протоколов тестов из comparison и не экспорт отчёта ОМ.
