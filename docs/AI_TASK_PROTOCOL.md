# Редактируемый протокол задания

Обновлено: 2026-10-21 14:20 UTC+3.

Канонический контракт Viewer 4.47.0. Протокол создаётся командой
«Инструменты → Создать протокол» и хранится в `<task>/DOCS/*.html`.
Это самостоятельный документ для просмотра без Viewer, сети и JavaScript.
Редактирование выполняется в Viewer, в том числе после перезапуска программы
и без первоначальных файлов результатов HDF5.

## Выбор видов

Флажок «В протокол» сохраняет снимок текущего вида и момента времени, а не
подписку на дальнейшие изменения графика. Для замены снимка надо снять и
поставить отметку снова. Флажок устанавливается после успешного захвата;
ошибка показывается рядом с ним. Переключение вкладок сохраняет снимки.
Успешная загрузка задания сбрасывает все отметки и снимки; ошибка загрузки
сохраняет прежнее задание и его выбор. Дозапись диапазонов не является новой
пользовательской загрузкой задания.

- Источники / Поле 3D: флажок перед кнопкой справки, снимок с текущим ракурсом.
- Рабочие точки и Поле на линиях: последний элемент панели графика.
- Поле в областях: справа общей панели, X/Y/Z объединены в одно изображение.
- Графики: отдельный снимок каждого графика; в обычном размере только флажок
  с подсказкой, в развёрнутом также подпись. Статическая таблица сохраняется
  таблицей HTML. Удаление графика снимает его отметку.

`ProtocolCheck.jsx` использует существующий lifecycle захвата renderReady /
prepare / capture / restore через `protocolCapture.js`. Восстанавливаются
масштаб, видимость кривых, ракурс и время. Захват блокирует другие операции,
имеет отмену и предел ожидания 15 секунд. App владеет коллекцией снимков.
Краткий комментарий содержит шаг, время, величины и выбранные объекты; его
можно изменить в диалоге перед сохранением.

## Файл и повторное редактирование

`protocolDocument.js` владеет схемой `clark-viewer-protocol`, версия 1.
В одном HTML находятся отображаемые блоки, встроенные PNG, стили и JSON в
`script[type="application/json"]#clark-protocol-data`. Исполняемых скриптов
и внешних ресурсов нет. Идентификатор документа, дата создания и стабильные
идентификаторы блоков переживают последующее открытие. Известные блоки:
`image`, `text`, `table`. Данные проверяются перед чтением и записью;
неизвестная версия или тип блока отклоняются, а не пропускаются.

Новый протокол включает путь от имени выбранного базового каталога и точный
текст `output3XX/conditions.json`, если файл существует. Абсолютный путь ОС
браузер не предоставляет. Условия уже созданного протокола не обновляются
скрытно: их можно удалить или добавить актуальный файл отдельной кнопкой.

«Открыть существующий» читает ранее созданный HTML из DOCS. Комментарии и
состав блоков доступны для изменения без пересчёта графиков. «Добавить
отмеченные» добавляет только отсутствующие идентификаторы снимков; прежние
комментарии сохраняются. Удаление блока снимает соответствующую текущую
отметку, если она существует. При сохранении физически записывается весь
HTML, но содержательно изменяются только выбранные пользователем блоки.
Просмотр доступен через кнопку «Просмотр HTML» или обычное открытие файла.

`taskProtocolService.js` владеет доступом к файлам. До «Сохранить в DOCS» нет
запроса write-разрешения или создания каталога. Имя ограничено конечным
именем `.html`; чужой HTML не заменяется. Перед записью существующий текст
сравнивается с открытой версией: изменение извне требует повторного открытия
или нового имени. Ошибка записи вызывает abort потока. Общий предел файла —
64 МиБ, максимум 200 блоков; текст условий — до 2 МиБ. Это не формат
протоколов тестов из comparison и не экспорт отчёта ОМ.
