# Выбор задания и отметка последнего открытия

Обновлено: 2026-10-23 14:47 UTC+3.

<a id="project-disk-access"></a>
## Диск и общий доступ с Editor — 4.48.0

Верхний список `Tasks.jsx` содержит непосредственные каталоги `clark.*`
выбранного диска без учёта регистра, кроме `clark.app`. Проекты перечисляются
в выбранном каталоге, задания — в проекте. При старте/F5 открывается
`ProjectDiskDialog`; только его кнопка запускает
`showDirectoryPicker({id:"clark-project-disk",mode:"readwrite"})`.
В основной панели кнопки смены диска нет. Закрытие начального окна позволяет
продолжить работу, повторное открытие выполняется перезагрузкой страницы.

В строке «Список проектов» справа стоят папка и ↻. Папка вызывает
`showOpenFilePicker` с `startIn` текущего каталога `clark.*` для просмотра
содержимого; результат и отмена не меняют выбор. ↻ перечитывает проекты,
сохраняет существующий выбор и очищает его после удаления проекта. Подсказки:
«Обновить список проектов» и «Обновить список заданий». Нижняя кнопка сохраняет
прежнее действие — перечитывание признаков состояния заданий.

`projectDiskAccessService.js` совпадает с Editor: хранит handle в общей
IndexedDB и уведомляет вкладки. Полный [межпроектный контракт](https://github.com/y26084670-blip/clark-editor/blob/main/docs/AI_CLARK_INTEGRATION.md#shared-project-disk)
принадлежит Editor. В том же профиле браузера и на том же origin Viewer может
восстановить диск без системного выбора, в том числе после закрытия Editor.
При `queryPermission` не равном granted появляется кнопка разрешения;
автоматический `requestPermission` запрещён. Отказ и недоступное хранилище
оставляют возможность явно выбрать диск. Служебные каталоги не открываются.

Первый каталог выбирается автоматически; при повторном выборе диска сохраняется
имя, если найдено. Проект и задание выбираются вручную. Пустой диск очищает
списки; отмена picker сохраняет прежний выбор. Изменение диска другой вкладкой
не переключает уже выбранный диск Viewer. Переключение каталога не сбрасывает
загруженное задание. Позднее восстановление не перекрывает ручной выбор;
повторное открытие того же каталога сохраняет handle для очередей записи.

Проверки: `test/taskDirectoryPermissions.test.js` и общий браузерный сценарий
`scripts/check-shared-disk-browser.mjs` в Editor с `VIEWER_ROOT`, указывающим
на Viewer. Он использует `test/browser/projectDisk.fixture.jsx`, настоящие
IndexedDB/OPFS и BroadcastChannel, подставной picker и управляемые разрешения.
Системные диалоги Windows этим стендом не проверяются.
На базе `a839ad8` для 4.48.0 прошли полный `npm test` (723 теста),
Pages-сборка и 12 общих браузерных сценариев с Editor 4.69.0.
[Свидетельства и среда](https://github.com/y26084670-blip/clark-editor/blob/main/docs/AI_VERIFICATION.md#verification-shared-project-disk).

## Файлы и позиции

После доступа `readwrite` к диску в выбранном базовом каталоге читается
собственный служебный файл в его корне:

| Приложение | Файл |
|---|---|
| Editor | `clark.editor-last-task.json` |
| Viewer | `clark.viewer-last-task.json` |

При первом доступе отсутствующий файл создаётся с пустыми позициями:

```json
{"version":1,"projectIndex":null,"taskIndex":null}
```

После успешного открытия задания запись заменяется целиком, например:

```json
{"version":1,"projectIndex":2,"taskIndex":3}
```

Номера начинаются с 1. Проекты и задания сортируются общей функцией
`sortTaskDirectories`: `localeCompare` для `ru` с `numeric:true`.
Позиции относятся к показанным спискам, а не к пути или постоянному ID.
Изменение состава/имён каталогов может изменить соответствие номера и имени.
Неизвестная версия, повреждённый JSON или некорректные номера дают сообщение;
позиция за границами текущего списка не отмечает строку.

## Когда обновляется история

Editor запоминает задание после подтверждённой успешной загрузки для
редактирования; Viewer — после успешной загрузки для просмотра.
Одиночный выбор строки и предпросмотр историю не меняют. Отмена отказа от
несохранённых изменений, ошибка загрузки и встроенное demo не заменяют запись.

При повторном выборе каталога восстанавливаются только отметки проекта и
задания. Автоматического выбора, открытия или загрузки задания нет.
При просмотре другого проекта его строки заданий не получают чужую отметку.

Очередь записи сериализована отдельно для каждого корневого handle и имени
файла. Session/revision не позволяют позднему чтению или записи прежнего
каталога менять текущую историю. При отказе записи уже загруженное задание
и новая отметка остаются в памяти; сохранённый JSON остаётся прежним и
показывается сообщение о неудачной записи. Другой файл приложения не меняется.

## Знак последнего открытия

`LastOpenedTaskMarker` рисует треугольник вправо: SVG `viewBox="0 0 12 12"`,
заливка `#ffff00`, обводка `#ff0000`. Он виден возле имени задания и проекта,
включая закрытое поле выбранного проекта. Названия и текущий выбор сохраняются.
Это отдельный знак истории; зелёная ✓ результата и сообщение об уже загруженном
задании имеют прежнее назначение.

Список проектов остаётся `<select>`. При поддержке `appearance:base-select`
раскрытые `<option>` показывают цветной SVG; `ProjectSelectValue` обновляет
содержимое первой кнопки при изменении истории без смены выбранного проекта.
Кнопка создаётся отдельным Solid-компонентом, чтобы HTML-шаблон не терял её
при разборе содержимого `<select>`. Мышь, клавиатура и событие `change` остаются
штатными. Старый нативный picker получает текстовый треугольник ▶;
цветная отметка в строках заданий от этого не зависит.

## HTML-протоколы по ячейке T в Viewer

Третий признак `T` определяется наличием каталога `comparison` в корне задания,
включая пустой каталог. `TaskStatusCells.jsx` показывает отдельную кнопку с
подсказкой «Есть каталог протокола сравнения: comparison. Щелчок — открыть все
HTML-протоколы тестов»; действие доступно мышью и клавишами Enter/Пробел.

`Tasks.jsx` передаёт handle именно той строки, по которой щёлкнули. Открытие
протоколов не требует загрузки задания, не меняет выделенную строку и запись
последнего успешного открытия. Строка списка имеет `role="option"`, кнопка `T`
останавливает всплытие одиночного и двойного щелчка. Enter/Пробел на самой строке
сохраняют выбор задания. Во время чтения повторный запуск и смена каталога
заблокированы.

`taskTestProtocolWindow.js` резервирует одно новое окно до первого `await`,
затем использует существующие `listTaskTestProtocols` и `readTaskTestProtocol`.
Рекурсивно открываются все `.html` без учёта регистра расширения, включая файлы
непосредственно в `comparison`. Имена и число уровней каталогов не ограничены
схемой решателя. Сортировка и чтение исходных байтов остаются за общим сервисом.

В окне создаются вкладки с полными относительными путями и отдельный `iframe`
для каждого HTML. Все документы загружаются сразу, интерфейс показывает выбранный.
Скрипты самодостаточных протоколов работают в своих документах. Ссылка позволяет
открыть текущий документ в отдельной вкладке браузера. Зависимости HTML по
относительным путям не переносятся; как и меню «Инструменты → Протоколы тестов»,
этот способ предназначен для самодостаточных HTML-протоколов.

Пустой или недоступный каталог закрывает подготовленное окно и сообщает причину
в Viewer. Ошибка отдельного HTML не мешает открытию остальных и выводится в окне
протоколов. Закрытие окна отменяет незавершённое чтение; его Blob URL освобождаются.
Удаление компонента отменяет ожидающие операции и освобождает ресурсы.

Проверки: `test/taskTestProtocolWindow.test.js` — пакетное открытие до/после
асинхронного поиска, полные пути, переключение вкладок, частичные ошибки,
блокировка окна, отмена и независимое освобождение URL. Рекурсивный поиск и
сохранение байтов покрывает `test/taskTestProtocolService.test.js`.

## Переход между Editor и Viewer

После успешного выбора задания через BroadcastChannel принимающее приложение
открывает свою вкладку заданий, выделяет строку и вызывает `window.focus()`.
Это запрос браузеру: независимо открытая вкладка может остаться на заднем плане.
При таком ограничении следует перейти на неё вручную; выбор уже выполнен.
Отказ `focus()` не отменяет выбор, не создаёт новую вкладку и не перезагружает
данные. При ошибке выбора или закрытии принимающей страницы фокус не запрашивается.
Транспорт и тест `taskSelectionChannel` синхронизированы между Editor и Viewer.

## Выбор из другого приложения — 4.49.1

Команды «Выбрать в Viewer» и «Выбрать в Editor» больше не зависят от совпадения
выбранных каталогов или ранее сохранённого списка. Явная команда передаёт
доступный diskHandle; получатель может перечислить его и выбрать каталог по
точному isSameEntry. Загруженное задание не меняется. Никаких фоновых запросов
разрешения или записей доступа эта команда не добавляет.
Полный [протокол и совместимость](https://github.com/y26084670-blip/clark-editor/blob/main/docs/AI_CLARK_INTEGRATION.md#explicit-task-selection)
принадлежит Editor; требуется Editor 4.74.0 для передачи diskHandle.

Владельцы: `src/services/taskSelectionChannel.js`, `src/tabs/Tasks.jsx`.
Общий сервис и `test/taskSelectionChannel.test.js` совпадают с Editor.
Проверка: профильные Node-тесты и `scripts/check-shared-disk-browser.mjs`
из Editor с VIEWER_ROOT. Новые случаи используют реально разные OPFS-диски
и каталог, добавленный после открытия принимающей страницы.
[Датированные результаты](https://github.com/y26084670-blip/clark-editor/blob/main/docs/AI_VERIFICATION.md#verification-contact-element).
